**v0.4.0 / 2026-11-19現在。** 取込から解析・診断・保存までの現行手順。構造クラスタリングと工程解析を同じ優先度で提供する。

## 起動

インストール不要の公開版は **https://yamadasmal.github.io/DSM/**。計算はすべてブラウザ内で行い、読み込んだデータは外部へ送信しない。以下は手元で起動する場合。

Node.js 26.13.1 / npm 11.20.0で確認済み。作業ルートで実行する。

```sh
npm ci
npm run dev
```

表示されたHTTP URLを開く。本番ビルドを確認する場合は `npm run build` → `npm run preview`。通常アプリのindex.htmlを直接ダブルクリックする起動は対象外。書き出した単独HTMLは直接開ける。

## 取込と表示

画面上部のタブ「データ／解析／結果／出力」で進む。データを確定すると解析タブが、結果が1件以上あると結果タブが選べる。解析が正常終了すると結果タブへ移り、取消した場合は解析タブに留まる（結果は結果タブで見られる）。用語や設定の説明は「?」アイコンや点線下線の語にマウスを重ねる（キーボードのフォーカス・タップでも表示）と出る。

1. サンプル、CSV/TSV、または.xlsxを選択する。ラベル有無・文字コード・区切り・方向を確認し、XLSXではシートとA1範囲を選ぶ。
2. 「検証してプレビュー」でエラー・警告・方向・変換履歴を確認する。列の対応、記号・欠損変換などは必要なものを明示選択し、再検証する。
3. 「このデータを確定」で有効データを切り替える。取消や不正データでは確定済みデータは失われない。
4. 構造／工程と手法を選び、解析閾値・二値化・手法の条件を設定し「解析を実行」。
5. 結果を選び、元DSMと結果DSM、指標、終了理由、診断を見る。設定を変更しても保存済み結果は書き換わらない。

内部規約は「行が列に依存」、情報の流れは列→行。逆規約の入力は転置して記録する。元セル表・元Aを保持し、解析用の零対角Dとmean対称化Sを別に作る。解析の閾値・二値化も元データを変更しない。

CSVはUTF-8を既定とし、Shift_JISは明示選択する。

ラベル／ID検索、ズーム、ドラッグパン、ホバー・クリック固定、矢印キーのセル移動、セル詳細と行の代替表を利用できる。対数配色・代替配色・対角表示も切り替えられる。同名ラベルは検索結果のIDで区別する。

手動順序変更は行と列を同時に移動する表示ビュー。ドラッグ／上下矢印、undo/redo、元順／解析順への復帰が使える。所属と元解析結果は上書きしない。工程では表示順を崩すと元のBand・先行順保証を適用できなくなるため、現在ビューの指標と警告を確認する。

## 手法を選ぶ

| モード | 手法 | 見る指標・特性 | 要素上限 |
| --- | --- | --- | --- |
| 構造 | 平均連結の階層法 | 結合距離で併合しkで分割。k変更時は併合履歴を再利用 | 500 |
| 構造 | 焼きなまし（所属） | mean Sの調整コストC_coord | 500 |
| 構造 | MCL（排他的抽出） | 行列の収束。所属抽出はアプリ独自 | 200 |
| 構造 | 汎用GA | C_coord、構造制約に対応。IGTAとは独立 | 500 |
| 構造 | IGTA+参照プロファイル | 有向DのTotalCost | 500 |
| 構造 | G-IGTA（IGTA++）参照プロファイル | Dの正規化に基づくMDL | 500 |
| 工程 | Tarjan SCC + Kahn | SCC、先行順、Band、フィードバック | 500 |
| 工程 | 焼きなまし（SCC内順序） | フィードバック重み、同点時は件数 | 500 |
| 工程 | Tearing | 循環依存を切る仮定の提案。元データは保持 | 500 |
| 両方 | 比較基準 | 全要素一群／全要素別群、入力順。最適化はしない | 500 |

構造の共通調整コストはmean Sで評価する。IGTA系の探索目的とは別であり、数値を同一の尺度として混ぜない。階層法は最適kや調整コストの大域最適解を保証しない。SCC法の内部は元index順で循環が残り、焼きなましでも解消の保証はない。Bandは資源制約を考慮した同時実行の保証ではない。

### 焼きなまし・MCLの条件

焼きなましの既定は100,000提案、100,101評価。初期解1回と温度調査100近傍を含む。無効提案も提案数を消費し、少ない評価予算では温度調査だけで終了する場合がある。構造の初期解は全単要素または階層法のkクラスタ。工程はSCC間を固定し、内部だけを交換する。指定予算の完了は数学的収束や大域最適を意味しない。

MCLはinflation=1.2〜5（既定2）、最大反復1〜100（既定100）。計算上の自己ループを加えるが、共通指標は解析Sで評価する。列最大を残してpruneし、行列の最大差1e-6未満が5回続けば収束する。列の最大行から排他所属を抽出する独自ルールで、公式mclとの一致は保証しない。

## 複数seedと結果比較

seedを使う手法はroot seedを入力するか「自動seedを生成」を押す。0も有効。既定10回、1〜100回を逐次実行し、全保存結果は100件まで。「複数seedの集計」で成功数、最良・中央値・最悪・母標準偏差を確認する。異なるseedが必ず違う解になるとは限らない。

「この結果の条件を設定へ」で具体的なseedと条件を戻すと反復数は1になる。同じ入力・版・seed・条件・固定予算なら同じブラウザ環境で再現できる。時間上限や取消までに進める量は環境負荷に左右される。

同じ入力ハッシュ・モード・前処理・指標版・共通α・制約・探索目的の版と係数等の結果だけを順位付けする。TotalCost、MDL、C_coordは異なる目的。削除・未実行・失敗の試行を統計に補わない。

取消はcancelled、時間上限やMCLの未収束はlimit-reached。暫定・未収束は通常の順位と成功例の統計から除外するが、表示・手動ビュー・保存はできる。Tearingは仮定を含むため常に通常順位から除外する。各手法の停止理由も確認する。

「解析を取消」は残りのseedも止め、取得済み結果と協調中断できた暫定最良解を保持する。計算は30秒上限、終了待ちは最大1秒。取消に1秒無応答ならWorkerを強制終了し、未取得の途中解は作らない。

## 汎用GAと構造制約

汎用GAの既定は50個体・200世代、トーナメント3、エリート2、交叉率0.8、要素ごとの突然変異率1/n。個体数4〜100、世代1〜500。n=1は即時終了。初出順に所属番号を付けた一様交叉は番号の対応に影響される。無制約では階層解・全単要素解を初期集団に含む。

「構造制約」にJSONを入力する。ペアは表示順位ではなく**元index（0始まり）**。4要素の例:

```json
{
  "mustLink": [[0, 1]],
  "cannotLink": [[1, 2]],
  "minClusters": 2,
  "maxClusters": 2,
  "maxClusterSize": 2
}
```

最初の2要素を同じ群、第2・第3要素を別群にし、2群・各2要素以下にする。ペアは種類ごとに10,000件まで。空欄は制約なし。群数・容量には元の要素数を使う。

対応は汎用GAのみ。未知キー、不正index、must-link内のcannot-link、同値類の容量超過、群数の明白な矛盾を拒否する。一般の矛盾をすべて事前判定するものではない。未対応手法へ変更する場合は制約を明示的に空欄へ戻す。

制約付きでは候補を修復し、得られた実行可能候補が不足すれば複製する。全て失敗した「実行可能解が見つからない」は数学的な実行不能の証明ではない。実行可能な初期集団の確定前の中断は結果を作らず、確定後は途中世代の評価済み最良候補を保持する。

## Tearingによる工程の仮定提案

工程モードで「Tearing」を選ぶ。循環内の最小重みの依存を仮想グラフから1つずつ除き、SCCを再計算する。同点は供給元→受取先の元index順。元A・元D・元セルは変更しない。

候補は供給元（列）→受取先（行）。重み合計、元Dと仮想Dのフィードバック、仮想順序と別Canvasを確認する。選んだ集合が最小とは限らず、依存重みは実際の仮定コストではない。削除の自動適用は行わない。

DAGに達するとcompleted。既定の辺数上限min(10,000,n(n−1))（n=1は1）、時間上限、取消を区別する。仮想DAG=falseなら循環が残る。500要素でも密な行列のDAG化を完走できる保証はない。元結果・手動ビューの指標と元SCC/Bandは元Dで評価し、仮想指標は別記する。

## IGTA参照プロファイル

[アルゴリズム仕様](IGTA_ALGORITHM_SPEC.md)を正本とする。原典由来と補完は[照合表](algorithms/igta-conformance.md)に区別している。**著者MATLABコードとの一致確認は未実施**。bus・重複クラスタ・構造制約は提供しない。

### 選択と条件

構造モードでIGTA+またはG-IGTAの「参照プロファイル」を選ぶ。目的値はIGTA+がTotalCost、G-IGTAがMDL。画面の調整コストC_coordはmean Sの共通評価で、目的値と同じ数値ではない。探索には非対称Dを渡し、原データを変更しない。G-IGTAは排他的クラスタで、bus・重複クラスタや構造制約を提供しない。

IGTA+はp、第二bid／無条件受理の確率の分母、提案上限を設定する。初期値はp=1、各分母10、提案100,000。bid指数4／規模指数1は固定。最高より小さい最大値を第二bidとし、全零では移動しない。現在コストの厳密改善だけ未試行リストをリセットする。新群は作らない。

G-IGTAは群スロット上限c_max、Q、G、評価上限、MDL係数、符号化を指定する。c_maxは表示された値を確認して明示的に設定する。UIの初期表示はmin(14,n)で、論文の普遍的既定値とは説明しない。APIはc_maxを省略できない。Q=36、G=36、評価1,332、alpha=0.1096／beta=0.8071、horizontalが初期値。共通C_coordのαとは別の係数。

Qは初期集団、Gは後続集団の世代数。評価上限は初期集団も含む。Q/Gを変えても評価上限を黙って書き換えない。初期Q本は全て生成してから合法化・評価する。各親ペアは交叉→子1変異・合法化・評価→子2変異・合法化・評価。合法化済み染色体を次の選択へ使い、全置換で失っても最良archiveを保持する。

### 実装上限

| 項目 | 上限・範囲 |
| --- | --- |
| 要素数 | 500（取込・各手法の入力上限） |
| IGTA+提案 | 1〜100,000 |
| TotalCost指数p | 0より大きく3以下 |
| 確率の分母 | 1〜1e9の有限数 |
| G-IGTA染色体 | c_max×n≤8,192ビット、1≤c_max≤n |
| G-IGTA Q | 偶数2〜72 |
| G-IGTA G | 0〜200 |
| G-IGTA評価 | Q以上14,472以下 |
| MDL係数 | 非負、合計1以下 |
| 計算時間 | 各試行30秒、終了待ち最大1秒 |

例えばn=500、c_max=17なら8,500ビットとなり実行を拒否する。値を16へ自動修正したり、行列から要素を削ったりしない。QやGの上限超過も同様。上限は全ての組合せで完走する保証ではない。長い予算・高密度では30秒で暫定解を返す。測定した条件・中央値・最大値・状態は [性能記録](benchmarks.md)。極端な重みでbidのべき乗が計算範囲を超える／正値から0になる場合は、暗黙の対数化や正規化をせずエラーにする。MDLの正規化で正の重みが0へ潰れる数値範囲もエラーにする。

### 結果・比較・保存

ITC終了と提案上限、予定世代完了と評価上限、取消と時間上限を区別する。予算上限や中断を「ITC収束」と表示しない。原典の大域最適性、著者の確率的結果、全近傍を調べたことを保証しない。既定10seedを逐次処理し、最良・中央値・最悪・母標準偏差を目的値で集計する。試行の全予定seedと各実行seedを保存する。

比較は同じ入力・前処理・指標版・共通α・目的の版と係数／正規化／群スロット条件に限定する。TotalCostとMDL、既存C_coordの値を一つの順位に混ぜない。共通C_coordも別の指標欄で確認できる。

HTML・XLSX・JSONに目的名／値／版／条件、実予算・停止理由・seed・初期解を保存する。解析DSMは方向を保持したDで、G-IGTA内部の正規化Pは目的値の定義として記録する。JSONは完了／予算／途中初期評価／途中世代の最良archiveを再計算して検証する。旧手法版も引き続き読める。

保存・再読込では保存済み結果をすべて再計算して検証し、進捗（i/n）を表示する。60秒間進捗がなければ中止する（総時間の上限はない）。多数結果・長時間の探索をまとめると時間がかかる。中止しても自動で結果を削らずエラーにする。必要に応じて保存対象の結果数や実行予算を利用者が減らす。

## 探索とクラスタの診断

結果を選ぶと「探索とクラスタの診断」が表示される。新しい探索結果で利用でき、以前に保存したJSONには途中履歴がないため、曲線が必要なら再実行する。実行中のライブ曲線ではなく、結果取得後の診断である。

- IGTA+: TotalCostの現在解と過去最良値。
- G-IGTA: MDLの評価候補と過去最良値。
- 汎用GA: 共通調整コストの評価候補と過去最良値。両GAの候補値は集団平均ではなく、初期集団も含む。
- SA: 構造は調整コスト、工程はフィードバック重みの現在解と過去最良値。悪化の受理も見える。
- MCL: 反復ごとの確率行列最大変化量。1e-6未満が5回という既存の収束条件を表示する。
- 階層法: 全併合の結合距離。選択kには先頭n−k回の併合を使用し、曲線はコストの最小化ではない。

横軸は探索が目的関数の評価回数、MCLは反復数、階層法は併合回数。グラフ上のポインター移動、または「履歴の位置」スライダーで値を確認できる。数値表も開ける。対数軸は全表示値が正のときだけ利用可能。

履歴は最大513点で初回・最終を保持する。間引きの観測間隔と総数を明示し、途中の変動や極値を省く場合がある。入力・探索予算・パラメータの自動縮小は行わない。

クラスタ規模分布は解析時の所属を使用する。外部依存比率は全要素一群でも0になるため、単独の品質基準にしない。「seed間の所属の安定性」は同手法・同評価条件の異なるseedの通常終了結果と選択結果をARIで比較する。ARI=1は同じ分割、0付近は偶然程度、負値もある。高い一致率やコストの停滞は良い分割・大域最適性の証明ではない。探索予算等が違う結果も対象になり得るので、各結果の条件も確認する。暫定・未収束は比較対象外。

セッションJSONで履歴を保存・再読込でき、保存値は再実行で照合する。単独HTMLは静的曲線・数値表・規模分布、XLSXは既存Metricsの履歴行とRunConfigに記録する。HTMLの曲線は線形表示で、アプリのスライダーやseed間ARI表は含まない。

検証結果と画面例は[探索診断の検証記録](validation.md#diagnostics)を参照。

## 保存と再開

「05 · 出力と保存」で選択結果・現在ビュー・タイトルを確認する。保存ファイルには入力情報を含む。出力開始時の対象を固定し、未実行の設定変更は含めない。

| 形式 | 用途と内容 |
| --- | --- |
| 単独HTML | 選択結果と現在ビューを閲覧・共有。file://でオフライン検索・ズーム・パン・セル詳細が使える。再解析は行わない。JavaScript無効でも概要・所属表は読め、印刷時は行列画像を表示 |
| XLSX | README / SourceMatrix / OriginalDSM / AnalysisDSM / ReorderedDSM / Elements / Metrics / RunConfig / Comparisonの9シート。原数式は文字列として保存し、式・リンクを生成しない |
| セッションJSON | 原セル、入力A、全保存結果、固定条件・seed・停止理由、現在ビューとundo/redo、タイトル・配色、探索履歴。再開用 |

再開は上の「入力ファイル」で.jsonを選択 → 検証・プレビュー → 確定。JSONの結果は再計算で照合する。元ファイルのバイト列・ファイル選択状態は復元しないので、原ファイル自体は別途保管する。自動保存・クラウド送信は行わず、ページ再読込で未保存のデータは失われる。

XLSXの行列を再取込するときは、1行目の説明を除く範囲を指定する。3要素のOriginalDSMならA2:D5。AnalysisDSM／ReorderedDSMを読み込むと元Aではなく解析・並べ替え済みの行列になる。Tearingの仮想DSM専用シートは追加していない。

## 上限と未確認事項

| 項目 | 制限 |
| --- | --- |
| CSV/XLSX | 20MiB、1〜500要素、ラベル200文字。MCLは200要素 |
| XLSX展開・範囲 | 実展開量100MiB、10,000エントリ、ヘッダー込み501×501、取込20秒 |
| セッション | UTF-8 JSON、64MiB、100結果、各ビュー履歴100変更。原セル文字列・式は各1Mi文字 |
| 解析 | 各試行30秒上限。計算Workerの終了待ちは最大1秒 |
| 出力・復元 | 60秒間進捗がなければ中止（総時間の上限なし） |
| XLSX出力 | 単一原セル文字列32,767文字まで。高度な装飾は保証しない |
| セッション互換 | schemaVersion=1、同梱の手法・実装版のみ。未知版は拒否。途中履歴のない旧JSONも読込可能 |

.xls・.xlsm・暗号化ブック、負の関係、複数関係、セル編集、共同編集は非対応。XLSXの結合・日付・真偽値・エラーセルは拒否する。非表示内容も選択範囲に含まれる。数式は再計算せず、保存済み数値の利用には明示設定が必要で、値が古い場合もある。巨大な申告範囲は利用者が範囲を指定して絞る。

保存・再読込は整合性再計算を伴うため、大きな行列・多数結果・長い探索予算の組合せでは時間がかかり、1件の再計算が60秒を超えると中止する。入力・結果・パラメータを黙って削らずエラーにする。必要に応じて利用者が保存対象の結果数や予算を減らす。入力や展開量の上限はプロセス全体のメモリ上限ではない。

Brave（Chromium）で検証。個別のChrome/Edge/Firefox/Safari、DPR=2、継続30fps、最大メモリ、著者MATLABコードとの一致は未確認。GitHub Pagesの公開版でも取込・解析の動作を確認済み（2026-11-19）。[検証記録](validation.md)と[性能測定](benchmarks.md)で条件・時点を確認できる。公開準備は[開発ガイド](development.md#配信と公開準備)を参照。
