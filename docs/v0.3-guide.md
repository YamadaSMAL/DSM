# v0.3 制約と設計支援

M6の汎用GA・構造制約・Tearingを追加した。取込・保存の基本は [v0.1](v0.1-guide.md)、seed・比較は [v0.2](v0.2-guide.md)。**M5のIGTA系は研究ゲート未通過で未提供**。

## 汎用GA

構造モードで「汎用GA（IGTA系とは独立）」を選ぶ。既定は50個体・200世代、トーナメント3、エリート2、交叉率0.8、要素ごとの突然変異率1/n。既定10seedを逐次処理する。単一試行は反復数1。上限500要素、個体数4〜100、世代1〜500。n=1は即時終了。

各要素の所属を染色体にする。両親を初出順に番号付けして一様交叉し、突然変異では他群または新群へ移す。この交叉は所属番号の対応に影響される。IGTAや原典準拠の研究手法とは異なる。

無制約の初期集団には階層解・全単要素解を含む。制約付きでは実行可能な候補へ修復するため、そのままの初期所属が残るとは限らない。適合候補が不足すれば得られた候補を複製し、全て失敗した場合は「実行可能解が見つからない」と表示する。大域最適や一般の実行可能性を保証しない。

## 構造制約

「構造制約」を開きJSONを入力する。ペアには**元index（0始まり）**を使う。表示順位を変えても対象は変わらない。例は4要素の場合:

```json
{
  "mustLink": [[0, 1]],
  "cannotLink": [[1, 2]],
  "minClusters": 2,
  "maxClusters": 2,
  "maxClusterSize": 2
}
```

最初の2要素を同じ群、第2・第3要素を別群にし、2群・各2要素以下へ制限する。ペアは種類ごとに10,000件まで。空欄は制約なし。省略した群数・規模は1〜n／最大n。群数範囲と規模には元の要素数を使い、must-link同値類の個数とは区別する。

対応手法は現在GAだけ。入力すると未対応手法は選択できず、既に選択されていても実行を拒否する。工程モードへ移る場合も明示的に空欄へ戻す。未知キー・不正indexを拒否する。must-link内のcannot-link、同値類が最大規模を超える場合、群数の明白な矛盾等は実行前に知らせる。これ以外の一般の矛盾を全て検出するものではない。

制約付きと制約なし、または異なる制約の結果は順位付けを分ける。結果の「この結果の条件を設定へ」で制約・seed・GA条件を復元できる。制約の入力はJSON保存・HTML/XLSXの条件にも残る。

## Tearing提案

工程モードで「Tearing」を選ぶ。循環内の依存のうち最小重みを一つ選んで仮想グラフから除き、SCCを再計算する。同点は供給元→受取先の元index順。元A・元D・元セルは変更しない。

候補一覧は「供給元（列）→受取先（行）」。重み合計、元Dのフィードバック、仮想Dのフィードバック、仮想順序と別Canvasを確認する。重みは実際の仮定コストではなく、選んだ集合が最小とは保証しない。設計判断に使う提案で、削除の自動適用はない。

DAGに達するとcompleted。辺数上限（既定はmin(10,000,n(n−1))、n=1は1）または30秒で未完ならlimit-reached、取消ならcancelled。仮想DAG=falseの場合は循環が残っている。上限500要素でも大きな密行列のDAG化を完走できるとは限らない。

Tearingは仮定を含むため通常の成功順位から常に除外する。元結果と手動ビューの指標は引き続き元Dで評価する。仮想指標は提案欄で別記し、元指標を0へ上書きしない。元SCCとBandは元Dのもの。

## 取消と保存

GAは実行可能な集団の初期化前に止まった場合、結果を作らず取得済み結果と入力を保持する。集団確定後は途中世代の評価済み最良候補まで保存する。実評価数・完了世代数・途中世代の子数を保存し、JSON読込で同じprefixを再実行する。Tearingも確定した候補辺まで保存・再現する。

セッションのスキーマは1のまま任意項目を追加。新手法の保存はv0.3以降で開く。過去の手法版も引き続き読める。HTMLは候補表・仮想順序・指標、XLSXは9シートのMetricsとRunConfigへ提案を記録する。両形式の元／解析／並べ替えDSMは元依存を保持する。仮想DSMの専用行列シートは追加していない。

保存・再読込は整合性再計算を伴い、長時間探索・多数結果では30秒の入出力上限に達する場合がある。必要に応じて結果数・世代・提案数を減らす。手動ビューは表示順の変更であり、所属制約や仮定候補を書き換えない。
