# v0.2 複数探索手法

取込・表示・保存・公開準備の基本は [v0.1手順書](v0.1-guide.md)。v0.2ではM4の探索と複数seed比較を追加した。追加依存はない。

## 手法を選ぶ

| モード | 手法 | 主な条件 | 上限 |
| --- | --- | --- | --- |
| 構造 | 平均連結 | k、α | 500 |
| 構造 | 焼きなまし（所属） | seed、初期所属、提案・評価予算、冷却 | 500 |
| 構造 | MCL（排他的抽出） | inflation、最大反復、α | 200 |
| 工程 | Tarjan SCC + Kahn | 有向Dの先行順・Band | 500 |
| 工程 | 焼きなまし（SCC内順序） | seed、提案・評価予算、冷却 | 500 |

構造はmean Sの調整コスト、工程はDのフィードバック重み・同点時の件数で比較する。構造と工程を同じランキングへ混ぜない。閾値・二値化・αなどの異なる条件は比較対象外になる。

## 焼きなましを実行する

1. データ確定後にモードと焼きなまし手法を選ぶ。
2. root seedを入力するか「自動seedを生成」を押す。0も有効。実行予定seedを確認する。
3. 既定の10回、または1〜100回を指定する。全結果を含めて100件以内にする。
4. 必要なら探索予算・冷却条件を変更して「解析を実行」。試行は逐次処理される。
5. 解析結果と「複数seedの集計」で成功数、最良・中央値・最悪・母標準偏差を見る。最良一例だけで品質を判断しない。

既定は100,000提案、100,101評価。評価数は初期解1回と温度調査100近傍を含む。無効提案も提案予算を消費する。評価予算を小さくすると温度調査だけで終了する場合がある。

指定予算を終えたcompletedは、その予算の探索が完了した意味で、大域最適や数学的収束を意味しない。温度調査と初期解、実際の提案・評価数は結果に保存される。構造は全単要素または階層法のkクラスタを初期値にできる。工程はSCC間を固定し、内部の交換だけを探索する。

同じ試行を再実行するには結果を選び「この結果の条件を設定へ」を押す。具体的なseedと条件が戻り、反復数は1回になる。入力・版・seed・条件・評価予算が同じなら同じブラウザ環境で結果が一致する。異なるseedが必ず異なる解になるとは限らない。

## MCLと暫定結果

MCLは計算上の自己ループを追加するが、指標は元の解析Sで評価する。最大200要素。inflationは1.2〜5、既定2。列最大を残してpruneし、最大差1e-6未満が5回続けば収束する。列の最大行で排他的に所属を決めるアプリ独自ルールで、公式mclコマンドとの一致は保証しない。

反復上限で未収束ならlimit-reached / converged=falseと表示する。取消はcancelled、時間上限はlimit-reached。これらは暫定結果で、通常ランキングと成功例の統計から除外する。表示・手動ビュー・保存はできる。

「解析を取消」は残りのseedも止める。既に受信した結果と、協調中断できた現在の暫定解を保持する。強制終了時に途中解を捏造しない。計算上限は30秒、終了待ちは最大1秒。取消に1秒応答がなければWorkerを強制終了する。

## 保存と制限

JSONは全試行seed、PRNG版、初期解、停止理由、収束状態、温度調査、現在ビューを保存する。v0.1のセッションも既存手法版なら読み込める。古いアプリは新手法を認識しないため、v0.2のファイルはv0.2以降で開く。

HTML/XLSXにも暫定状態とseed・条件・集計を記録する。保存・読込は再計算による検証を行うため、大きな行列・多い結果・長い探索予算では入出力の30秒上限に達する場合がある。必要に応じて結果を減らして保存する。セッションは64MiB、100結果、各ビュー履歴100件まで。削除・未実行・失敗の試行を統計に補わない。

Braveで検証。製品別ブラウザ互換性、DPR=2、継続30fps、最大メモリ、GitHub上の実公開は未確認。性能記録は [benchmarks.md](benchmarks.md)、検証は [M4-validation.md](M4-validation.md)。IGTA++はM5の原典照合後に扱い、今回の焼きなましやMCLを代用しない。
