## 1. 目的と仕様の読み方

CSV / XLSXで与えられたDesign Structure Matrix（DSM）をブラウザ内で読み込み、複数手法による解析、対話的な比較、単独HTMLレポートとXLSXの出力を行う。研究と設計検討の両方で、結果の意味・前処理・評価式・乱数条件を追跡できることを重視する。

本書の「必須」は該当する実装段階の受入条件。「初期仮定」はユーザー回答により変更できる設計判断であり、合意済みとは扱わない。「研究ゲート」は原典との照合を完了するまで正式なアルゴリズム名で公開しない条件を指す。性能数値は実測結果ではなく、検証する目標である。

成果物は静的なHTML / CSS / JavaScriptとなる。TypeScriptは開発時にJavaScriptへ変換する。GitHub Pagesは静的サイトを配信するため、ファイル処理と計算をクライアントで完結させる設計とする。[GitHub Pages公式説明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

## 3. 対象範囲とリリース構成

### 3.1 二つの解析モード

**構造モード（部品・組織）**: 関係の強い要素をモジュールへ分割する。各要素は必ず一つのクラスタに所属する。クラスタを連続表示する並び順と、所属自体を区別する。

**工程モード（タスク・設計変数）**: 依存方向を保ち、強連結成分（SCC）による循環ブロックの抽出、ブロック間の順序付け、ブロック内の順序改善を行う。SCC抽出だけで循環を消したり、その内部を最適化したりしたと説明しない。DSMのブロック三角化とSCCの関係はHossainの論文を参照する。[Efficiently Computing with Design Structure Matrices](https://www.designsociety.org/download-publication/30378/efficiently_computing_with_design_structure_matrices)

### 3.2 段階別の完成形

| 段階 | 内容 | 位置付け |
| --- | --- | --- |
| M0 | 形式・方向・指標の固定、最小テストデータ | 設計基盤 |
| M1 | CSV/XLSX取込、検証、Canvas DSM表示 | データ確認版 |
| M2 | 階層クラスタリング、Tarjan SCC + Kahn順序、指標 | 最小解析版 |
| M3 | HTML/XLSX/JSON出力、再現性、Pages配信確認 | 初版v0.1 |
| M4 | 焼きなまし（所属・順序）、MCL、比較・複数seed | 複数探索手法版v0.2 |
| M5 | IGTA+、IGTA++候補の原典照合・検証・実装 | 研究手法拡張版 |
| M6 | 汎用GA、制約、Tearing提案 | 実務拡張版 |

本仕様全体には複数のクラスタリング・工程解析手法を含める。v0.1では入力・表示・出力の一貫性を先に成立させ、v0.2で目的関数を使う探索の比較まで提供する。IGTA系をv0.1必須へ変更する場合、M5を前倒しし、研究ゲートを省略しない。

両モードは同じ優先度とする。M2は階層クラスタリングとSCC／順序付けの両方、M4は構造の探索と工程の順序改善の両方が完了して初めて段階完了とする。一方だけの完成を理由に他方を次版へ後回しにしない。初回画面では両モードを対等な選択肢として提示する。

初期対象外: サーバー、ログイン、共同編集、クラウド保存、AI APIによる解析、負の関係、重複クラスタ、複数層DSM、作業時間／資源を使うスケジューリング、アプリ全体のPWA化。Bandingは依存上の並列候補であり、実際に同時実行可能と保証しない。

## 4. 行列の意味と内部モデル

### 4.1 方向と添字の規約（全機能で必須）

- 内部行列 `A[i,j] > 0` は「要素iが要素jから情報を必要とする」を意味する。
- 工程グラフは **j → i**。供給元・先行タスクがj、受取先・後続タスクがi。
- 先行から後続へ並べると通常の依存は対角より下になる。対角より上をフィードバックと定義する。
- 表示順 `order[p]` は「表示位置pに置く元の要素index」。表示値は `B[p,q] = A[order[p], order[q]]`。行と列に同一の置換を適用する。
- 非対称行列を勝手に対称化しない。構造モードの手法に必要な場合のみ、別の派生行列を生成する。
- 対角の入力値は原データとして保存し、解析時は0にする。自己依存・期間・属性には初版で解釈しない。非ゼロ対角を警告する。

例: BがAに依存するなら行B・列Aが1、グラフはA → Bとなる。この例を取込画面・ヘルプ・自動テストで共通利用する。

### 4.2 識別子と保存形式

ラベルとIDを分離する。内部IDは確定した取込順に `e000001` 等を割り当て、並べ替え後も維持する。重複ラベルは許可するが警告し、入力上の照合には使えない場合がある。indexは0始まり、出力の表示順位は1始まり。

```ts
type Element = { id: string; label: string; originalIndex: number };
type AnalysisMode = 'structure' | 'process';
type MatrixData = {
  schemaVersion: 1;
  revision: number;
  elements: Element[];
  n: number;
  values: Float64Array; // row-major、方向正規化後。対角の元値を含む
  convention: 'row-depends-on-column';
  provenance: {
    sourceName: string;
    sourceSha256: string;
    sheet?: string;
    range?: string;
    importOptions: Record<string, unknown>;
    transformations: Transformation[];
  };
};
type Transformation = {
  kind: string;
  params: Record<string, unknown>;
  affectedCells: number;
};
```

原ファイルのバイト列ハッシュと、正規化データのハッシュを別に保持する。後者は要素ID・ラベル、行列、方向、前処理条件を所定順に直列化してSHA-256化する。計算条件の変更で異なるハッシュになる。元ファイルの永続保存はしない。

行列の正規化前のセル表はセッション中に保持し、`SourceMatrix`へ書き出せるようにする。CSVの引用符やXLSXの書式まで復元する「原ファイル複製」は保証しない。

### 4.3 派生データと前処理パイプライン

順序を固定する: 範囲確定 → ラベル照合 → 値変換 → 方向正規化 → 対角除外 → 解析閾値 → 手法固有の変換。

解析用有向重み `D[i,j] = A[i,j]`（i≠jかつA[i,j]>τ）、それ以外は0。既定 `τ=0`、単位は元の重みと同じ。二値化オプションは閾値適用後の正値を1にする。閾値・二値化は解析条件として記録し、表示だけの非表示フィルタと分ける。

構造用の無向重みは `S[i,j]=(D[i,j]+D[j,i])/2`、対角0。対称入力の値の倍増を避ける。代替としてsum/maxを後日追加できるが、v0.2まではmeanで固定する。工程モードは対称化しない。手法ごとの自動スケーリングは行わない。

元DSM、方向正規化DSM、解析に使ったD/S、表示順を別に管理し、エクスポートで追跡できるようにする。

## 5. CSV / XLSX取込

### 5.1 共通形式

初版は正方の行列形式のみ。エッジリストは将来拡張とする。次の二形式を明示選択できる。

```csv
,A,B,C
A,0,0,0
B,1,0,0
C,0,1,0
```

ラベル付き: 先頭行は列ラベル、先頭列は行ラベル。左上セルは空または任意文字列。ラベルなし: n×nの数値領域であり、`要素1`〜を生成する。上の例はA → B → Cの工程DSM。

ラベルは前後空白を除去する。異なるUnicode文字列の同一化や大文字小文字の統一はしない。空ラベルはエラー。全ラベルが一意で、行・列集合が一致すれば列を行ラベル順へ合わせられるが、並べ替え内容を提示して適用させる。重複ラベルがある場合は行列のラベル列が位置ごとに一致することを要求し、自動照合を禁止する。不一致を黙って修正しない。

### 5.2 CSV

- Papa Parseを候補とし、引用符、区切り内改行、CRLF/LF、BOMを扱う。文字列のsplitによる独自解析は禁止。[公式仕様](https://www.papaparse.com/docs)
- 既定UTF-8（BOM可）。Shift_JISは利用者が文字コードを指定した場合のみ対応し、プレビューで確認する。復号エラーを置換文字で黙殺しない。
- 区切りはカンマ／タブ／セミコロンから推定し、選択変更できる。小数点はピリオド。小数カンマ、桁区切りカンマは初版で非対応。
- 行内の空セルは保持し、末尾の完全な空行だけ除く。途中の空行、長さの異なる行はエラー。
- 動的な型推定はせず、ラベル文字列と行列数値を別に変換する。`001`というラベルを保持する。

### 5.3 XLSX

- SheetJS CEを候補とし、Fileから取得したArrayBufferを読み込む。ブラウザでファイルパスによるreadFileを使わない。[公式入力ガイド](https://docs.sheetjs.com/docs/solutions/input/)
- `.xlsx`のみ必須。`.xls`、`.xlsm`、パスワード保護ブックは非対応と明示する。
- シート名とA1形式の範囲を選択。プレビューからヘッダー有無を変更できる。非表示シート／行／列も選択範囲内なら含むことを通知する。
- 選択範囲の結合セル、エラー値、日付型、真偽値は拒否する。書式上の表示値より数値セルの内部値を採用する。
- 数式セルは既定で拒否し、座標を示す。詳細設定で「保存済み計算値を利用」を選んだ場合のみ、有限の数値キャッシュを使用できる。ブラウザ内再計算なし、キャッシュが古い可能性と該当座標を記録。キャッシュなしは拒否。
- セルの型・値・数式を区別して読み取る。[SheetJSセルモデル](https://docs.sheetjs.com/docs/csf/cell/)

### 5.4 値の解釈と検証

| 入力 | 既定の扱い |
| --- | --- |
| 非負の有限実数、科学表記 | 許可。`-0`は0に正規化 |
| `X` / `x` / `×` | 「記号を1へ変換」が有効な場合のみ1。既定無効 |
| 空セル | エラー。「空セル=0」を明示選択した場合のみ変換・件数表示 |
| 負値、NaN、Infinity、文字混在の数値 | エラー |
| 対角の空セル、`-` | 対角専用オプションで0扱い可。適用を記録 |
| 非対角の `-`、N/A、`#VALUE!` 等 | エラー |
| 非対称性 | 許可。非対称であることを表示 |
| すべて0 | 許可。情報なしの警告。指標の未定義に対応 |
| n=0、非正方 | エラー |
| n=1、孤立要素 | 許可 |

エラーはファイル・シート・セル座標・元文字列・理由・修正方法を提示する。最初の100件を表示し、総件数も示す。解析ボタンはエラー解消後だけ有効。プレビュー中の取消で現在の有効データを失わない。

初期制限: ファイル20MiB、n≤500、ラベル200文字。XLSXの申告範囲をそのまま全面走査せず、選択範囲を検証する。展開サイズ100MiB、エントリ数10,000、取込Workerの20秒制限を設ける。ZIPメタデータだけに依存せず実展開量を制限できる手段をM1で検証し、利用ライブラリで保証できない場合はその制約を記録してサイズ制限を引き下げる。制限超過は安全に中断する。

## 6. 評価指標と比較規則

以下は**本アプリが定義する指標**であり、すべての文献に共通する唯一のDSMコストではない。指標名、版、パラメータを結果に保存する。IGTA系の文献指標をこの式で代用して原典準拠と称さない。

### 6.1 構造モード

所属 `c(i)`、クラスタ規模 `s_g`、無向重み `S`に対し、i<jの各ペアを一度だけ数える。

```text
T = Σ(i<j) S[i,j]
E = Σ(i<j, c(i)≠c(j)) S[i,j]
R_external = E/T                         (T=0なら未定義)
C_coord(α) = Σ(i<j) S[i,j] × {
  s_c(i)^α   if c(i)=c(j)
  n^α        otherwise
}
```

`coordination-mean-v1`、既定α=1（0<α≤3）。規模の大きな単一クラスタを抑えるため内部結合にも規模コストを掛ける。外部結合比だけを最小化すると単一クラスタが有利になるため、単独で推奨順位に使わない。αの変更は別の実験条件とする。

クラスタ数、最小・最大・平均規模、内部重み `T-E`、外部重みE、外部比、C_coordを表示する。全0ならR_externalは「—（関係なし）」、C_coordは0。重みやαの大きさで有限値を超える計算はエラーにし、Infinityで順位付けしない。

### 6.2 工程モード

表示行列 `B_D[p,q]=D[order[p],order[q]]` に対して:

```text
F_weight = Σ(p<q) B_D[p,q]               // 上三角のフィードバック重み
F_count  = #(p<q and B_D[p,q]>0)
R_feedback = F_weight / Σ(i≠j) D[i,j]     // 分母0なら未定義
```

`feedback-weight-v1`はF_weightを最小化し、同点ならF_countを最小化する。SCC数、最大SCC規模、非自明な循環ブロック数、SCC間フィードバック重み（正しい順序なら0）、Band数も示す。SCC内部に循環があればフィードバックは一般に残る。

### 6.3 比較可能性

同一入力ハッシュ、モード、解析前処理、指標版・パラメータ、制約条件の結果だけを共通指標で順位付けする。手法固有の目的値（MDL等）を異なる指標と直接比較しない。構造コストと工程コストを一つのランキングに混在させない。

複数seedは既定10回。最良・中央値・最悪・標準偏差・成功件数を表示し、単一最良例だけで優位性を主張しない。決定的手法のseed反復は不要。クラスタIDは番号自体に意味がないため、比較では各所属集合を正規化する。安定性評価は後続でARI等を追加できるが初版の必須ではない。

### 7.2 凝集階層法

Sの最大非対角値をw_maxとし、`d(i,j)=1-S[i,j]/w_max`。w_max=0なら異なる要素間は1。これは直接結合に基づく非類似度で、ユークリッド距離を仮定しない。Ward法は適用しない。

単要素クラスタから開始し、平均ペア距離が最小の二クラスタを併合する。距離同点（許容差1e-12）なら所属元index集合の辞書順で決定。既定kは `min(n,max(2,round(sqrt(n))))`、n=1なら1。ユーザーは1≤k≤nを指定する。自動で「最適k」と説明しない。

クラスタ間平均距離は規模で重み付けして更新する。全併合履歴を保存しk変更時に再利用する。クラスタは最小元index順、内部は元index順に表示する。描画順の最適化は別機能とする。単純実装の最悪O(n³)を明記し、M2で500要素の計測を行う。

### 7.3 SCC / Partitioning / Banding

1. Dの正値から j → i の隣接リストを構築する。
2. TarjanでSCCを抽出し、各SCCを一つの頂点に縮約したDAGを作る。重複辺は一つにする。
3. Kahn法で先行から順に出力する。同時に取り出せるSCCは最小元index順。
4. SCC内は初版では元index順。M4でSCC内だけ順序最適化する。
5. Bandは縮約DAG上で、入次数0をlevel 0、他を `1+max(先行level)` とする。SCCを跨ぐ要素は同一SCCのBandに置く。

SCC計算は隣接リストに対しO(n+m)。密行列からの辺抽出はO(n²)。再帰の深さに依存しない実装を優先する。SCCの所属は一意だが、独立したブロック間の有効な順序は複数あり得る。

### 7.4 焼きなまし法（共通）

以下は本アプリの設計値であり特定論文の再実装ではない。

- 最大提案数100,000、冷却区間1,000提案、温度倍率0.95、初期温度は有効な近傍100個の正のΔの中央値を `-ln(0.8)` で割った値。正のΔがなければ1。
- 改善または同点は受理。悪化Δ>0は `exp(-Δ/T)` の確率で受理。乱数uを引き `u < exp(-Δ/T)` で判定する。
- 現状態と最良状態を分離する。最良を常時保持し、上限終了でも最良を返す。
- 無効提案も提案数に数える。初期温度調査の評価数は別に記録する。
- 上限・停止条件・温度下限1e-12を設定化する。全パラメータを保存する。

所属版: 単要素クラスタから開始（利用者選択で階層法結果を初期値にできる）。要素を一様選択し、現在以外の既存クラスタと新規単要素クラスタから移動先を一様選択する。空クラスタを除去し、最小元index順でID正規化。目的はC_coord。初期値の作成条件も記録する。n=1は即時終了。

順序版: SCC/Kahnの並びを初期値にし、規模2以上のSCCをその要素数に比例して選択、その中の異なる二位置を一様選択して交換する。SCC間順序は固定。目的はF_weight、同重みではF_countで比較する。受理確率は重みΔに基づき、同重み・件数悪化は同点扱いで受理してよいが、最良更新は辞書式目的値による。全SCCが単要素なら即時終了。

### 7.5 MCL

MCLの核は確率遷移行列のexpansionとinflationの反復である。[原著者の実装・文献案内](https://github.com/micans/mcl)

アプリでの実装仕様:

1. S/w_maxに対角1の自己ループを追加（全0なら単位行列）。列和を1に正規化。
2. expansionは通常の行列積 `P ← P²`。
3. inflationは要素ごとの累乗 `P_ij ← P_ij^r`、既定r=2、範囲1.2〜5。
4. 列最大を必ず残し、1e-8未満をpruneして列正規化。丸め等でゼロ列ならその要素の自己ループを1に戻す。
5. 連続する行列の最大絶対差が1e-6未満の状態が5回続けば収束。最大100反復。
6. 抽出は**アプリ独自の排他的ルール**: 各列jで最大の行aをattractorとし、同点は最小元index。同じaを選ぶ要素を一群とする。すべての要素を一つのクラスタに割り当てる。

抽出規則やpruningによって公式mclコマンドと同一にならない場合があるため、`mcl-exclusive-v1`と表示する。未収束ならその旨を示し、成功扱いのランキングから既定で除外する。密行列積は反復あたりO(n³)なので初期上限n=200。500要素対応を他の手法から類推しない。自己ループは計算用であり、指標のSには含めない。

### 7.6 IGTA / IGTA+ / IGTA++の研究ゲート

IGTAはIdicula–Gutierrez–Thebeau系のDSMクラスタリングを指す。IGTA+の2012年論文は、Thebeauの確率的山登り法に対する効率と結果品質の改善を報告する。[著者所属機関の書誌・要旨](https://research.aalto.fi/en/publications/improved-clustering-algorithm-for-design-structure-matrix/)、[論文収録の学位論文](https://kth.diva-portal.org/smash/get/diva2%3A530891/FULLTEXT02.pdf)

2013年のBörjesson & Sellgren論文は、GA・知識を利用するヒューリスティック・MDL指標を扱うことが要旨から確認できる。一方、後続文献のIGTA++という呼称と、当該論文の各手法の厳密な対応は本文との照合が必要である。**「汎用GA + 局所探索 + 本アプリのC_coord」をIGTA++と呼ぶ実装は禁止する。** [著者公開の論文情報・要旨](https://www.researchgate.net/publication/267490581_Fast_Hybrid_Genetic_Clustering_Algorithm_for_Design_Structure_Matrix)、[後続研究でのIGTA++使用例](https://www.designsociety.org/download-publication/40949/The%2Bhunt%2Bfor%2Bproper%2Brelation%2Bweights%2Bin%2Bproduct%2Barchitecture%2Bclustering)

M5の着手時に `docs/algorithms/igta-conformance.md` を作り、次を埋める。

| 照合項目 | 必須記載 |
| --- | --- |
| 出典 | 著者、年、題名、DOI、版、参照したページ・式番号 |
| 名称 | 原典内の表記、IGTA+／IGTA++／G-IGTA等との対応。未確認を明示 |
| 目的関数 | TCC/MDL等の完全な式、二重計数、対角、重み対応、パラメータ |
| 状態 | クラスタ表現、初期化、重複所属の可否 |
| 探索 | bid式、同点、乱数、受理、選択、交叉、突然変異、ヒューリスティックの詳細 |
| 停止 | 安定判定、世代・反復上限、最良解保持 |
| 再現 | 入力行列の入手元、参照出力、数値許容差、再現できない理由 |
| 差分 | 数値安定化、排他所属化、重み付き拡張など原典からの変更 |

原典の式・手順を確定できなければ機能は未提供とし、推測で穴埋めしない。他の段階は継続できる。研究ゲート通過は「正解クラスタが一例と似た」だけで判定せず、目的関数と各操作の照合・テストを必要とする。確率的結果の一致と目的値の整合を分けて評価する。原典との変更がある実装は別IDにする。

### 7.7 汎用GA（M6）

IGTA系と独立に実装。目的はC_coord。染色体はn個の所属番号、初出順に番号を再割当てする。既定個体数50、世代200、トーナメント選択3、エリート2、交叉率0.8、要素ごとの突然変異率1/n。

交叉前に両親を初出順で正規化し、一様交叉で各遺伝子を確率1/2で選択する。この方式が所属番号の対応に影響されることを文書化し、後から別の交叉方式を追加する場合は実装版を変える。突然変異は他の既存群または新規単要素群へ移動し、正規化する。初期集団は階層解1個、単要素解1個、残りをseedでランダム生成する。n=1は即時終了。最良解を失わないことを検証する。

### 7.8 Tearingと制約（M6）

Tearingは元依存を削除する編集ではなく、循環解消のため仮定・後回しにする依存の**提案**。D上で循環に属する辺のうち最小重みを選び、仮想グラフから除いてSCCを再計算する。重み同点なら供給元・受取先元index順。DAGになるまで繰り返す。最小重みは仮定コストの代用にすぎず、最小フィードバック辺集合を保証しない。候補辺、合計重み、仮想順序、元DSMを併記する。元のF_weightと、仮想グラフのF_weightを区別する。

制約は構造モードのmust-link / cannot-link、クラスタ数範囲、最大クラスタ規模。must-linkを同値類にし、矛盾するcannot-linkや規模上限を事前検出する。一般の実行可能性は自明とは限らないため、探索不成功を「数学的に実行不能」と断定しない。対応する手法だけを選択可能にし、未対応制約を無視しない。研究手法へ制約を追加する場合も原典版と別IDにする。

### 8.1 実行契約


手法を登録表へ追加することで、設定画面・検証・実行・比較表へ組み込める。UIから任意コードを実行するプラグイン読込は提供しない。

### 8.2 Workerと中断

取込・計算・大きな出力処理はWeb Workerで実行する。メインスレッドは表示とユーザー操作を担う。WorkerメッセージにはrunIdとdataRevisionを必須にし、古い応答を現在のデータへ適用しない。

進捗は最大毎秒5回、反復数・評価回数・最良値・経過時間を表示。所要時間不明の段階で架空の進捗率を出さない。複数seedは既定で逐次処理し、比較的少ないメモリで完了させる。

中断メッセージをWorkerが処理できるよう、短い計算チャンクごとにイベントループへ制御を返す。メッセージだけで止まらない同期ループを作らない。通常1秒以内に中断し、応答がなければWorkerをterminateして再生成する。直近チェックポイントがあれば取消済み暫定解として保存できるが、completedと表示しない。

配列の転送で元DSMをdetachしないよう、Worker用コピーを転送する。SharedArrayBufferやcross-origin isolationを必須にしない。失敗時は入力と完了済み結果を保持する。

### 8.3 再現性

- PRNGはmulberry32等、実装を固定した32bit seed方式（seedは0〜2³²−1）。Math.randomを計算経路で使わない。
- 自動seedは実行前に生成して表示・保存。複数実行はroot seedから所定の32bit加算で導出し、全seedを保存する。
- 同一seed・同一版・同一入力・同一パラメータ・評価回数上限で同一ブラウザ環境の結果が一致することを必須とする。
- 再現用は提案数・評価回数で停止。時間上限による停止は実機依存なので、再現性の対象外として記録する。既定30秒の安全上限に達したらlimit-reachedと表示する。
- ブラウザ間の浮動小数点差は完全なビット一致を保証しない。環境情報と許容差を出力し、同点選択を固定する。
- 表示順、所属、パラメータ、実装版、アプリcommit、前処理、指標版、初期解、停止理由を保存する。

手動並べ替えは元の解析結果を上書きしない。派生ビューとして履歴を作り、工程指標を再計算する。手動でSCC間の順序が崩れた場合、元のBandや順序保証を現在のビューにそのまま適用しない。

## 10. 出力と再読込

### 10.1 共通規則

出力対象は利用者が選択したスナップショット。実行途中に別の結果へ切り替えても内容が混在しない。出力処理時に入力ハッシュと指標を再検証する。既定名は `dsm_<安全化した名称>_<YYYYMMDD-HHmmss>.<ext>`、日時にはタイムゾーンもメタデータへ保存する。

### 10.2 単独HTMLレポート（M3必須）

1ファイルにスタイル、閲覧用スクリプト、データを埋め込み、ダブルクリックでfile://から開く。fetch、外部ライブラリ、CDN、外部フォントを使わない。

含める内容: タイトル、作成日時、入力情報、方向、前処理、手法・版・パラメータ、seed、停止理由、指標、元DSMと結果DSM、クラスタ／SCC所属表、並び順、警告。ズーム・パン・検索・セル詳細のみ対話操作でき、再解析は行わない。JavaScript無効でも概要と所属表は読める。

入力ラベルをHTMLとして解釈しない。DOM挿入はtextContent。埋込JSONは `<` をUnicode escape化する等、`</script>`で抜けられない直列化を行う。外部通信・ナビゲーションを生成しない。n=500を含む出力でも巨大なHTMLセル表を生成せず、行列はCanvasで描く。印刷用に概要・指標・所属表・行列画像を用意する。

### 10.3 XLSX（M3必須）

| シート | 内容 |
| --- | --- |
| `README` | 読み方、依存方向、日時、アプリ版、ハッシュ、各シートの役割 |
| `SourceMatrix` | 選択範囲の変換前セル値。数式は実行しない文字列として保存 |
| `OriginalDSM` | 方向正規化後のA、取込時の対角を保持、元の要素順 |
| `AnalysisDSM` | 実際に使ったDまたはS、対角0、元の要素順 |
| `ReorderedDSM` | AnalysisDSMを選択ビュー順で行列同時置換 |
| `Elements` | ID、ラベル、元順位、表示順位、構造クラスタ／SCC／Band |
| `Metrics` | 指標名・版・値・方向・単位・未定義理由 |
| `RunConfig` | 全パラメータ、変換条件、seed、実装版、停止理由、環境 |
| `Comparison` | 比較対象runの条件と共通指標。比較不可能な行は明示 |

選択した一結果の詳細を上記へ出力し、比較対象はComparisonに要約する。複数結果の詳細は個別出力とする。元・解析・並べ替え後のどの行列かを各シート上にも記載する。

数値は数値セル、ラベルは明示的な文字列セルで出力する。先頭`=`等を式として扱わず、ラベルや原数式からf属性を生成しない。ハイパーリンクを勝手に作らない。計算済み指標は値として出力し、Excel再計算に依存しない。高度なスタイルはライブラリの対応をM1で確認し、必須はヘッダー・列幅・型・データの正確性とする。

### 10.4 セッションJSON

型配列は数値配列へ変換。schemaVersion、正規化入力、原セル値、前処理、結果、ビューを保存する。アプリで再読込でき、同じ解析条件で再実行できる。ファイル選択状態や原ファイルのバイト列は復元しない。未知のスキーマ版、サイズ超過、不正な順列・所属・型は拒否する。JSON.parse後に検証し、任意オブジェクトをアプリ設定へ無検証でマージしない。

CSV結果出力は追加候補。追加する場合は元ラベルの保持とExcel向け安全化を分け、Papa ParseのescapeFormulae等を利用する。[公式出力設定](https://www.papaparse.com/docs)

Viteで `dist/` を作りGitHub Actions経由で配信する。プロジェクトURLは `base: '/<repository>/'`、ユーザーサイト／独自ドメインは `/` を用いる。公開先から設定し、リポジトリ名をコード中へ散在させない。[Vite公式のPages配信手順](https://vite.dev/guide/static-deploy)

初版は単一画面で、ルーティングが必要ならhash方式を使用する。Worker、サンプル、動的importもbase配下で解決する。トップレベルの `/assets/...` を固定しない。ビルド成果物を `/test-repo/` で配信するE2Eを設ける。

PRでは型検査・単体・E2E・ビルドを実行。mainへのマージ後にPages用artifactを配信する。deploy jobだけに必要なPages/id-token権限を付ける。実装段階では外部公開の設定まで準備し、実際の公開先・リポジトリは別途決定する。

アプリの通常起動はHTTPS配信を前提とする。`dist/index.html`のダブルクリック動作は必須にしない。単独HTMLレポートのみfile://動作を保証する。

## 12. 非機能要件

- 入力ファイル・行列・ラベル・解析結果をネットワーク送信しない。解析API、広告、分析用テレメトリーを組み込まない。
- 初回のアプリ取得は通信を伴う。GitHub Pagesのホスティング側のアクセスログとは区別して説明する。[GitHub Pagesのデータ収集説明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)
- 全ライブラリをビルドに同梱し、操作中の外部CDN依存をなくす。読み込んだデータは既定でメモリのみ。localStorageに行列を自動保存しない。
- 利用者が出力したHTML/XLSX/JSONには入力情報が含まれることを、出力画面の説明で示す。
- ラベル、ファイル名、メタデータを未信頼文字列として処理する。メッセージやセル内容を命令・スクリプトとして実行しない。
- ブラウザの現行安定版Chrome / Edge / Firefox / Safariを対象に、M0で具体的な検証版を記録する。

### 13.2 数学的な不変条件とオラクル

- 任意の結果のorderは0〜n−1の重複・欠落のない順列。所属は各元要素を一度だけカバーする。
- 並べ替えと逆置換で元行列を完全復元する。行和と列和の変化は同じ置換で説明でき、全重みは保存される。
- SCCの内部は相互到達可能。縮約グラフはDAG。n≤8では独立実装の推移閉包から求めたSCCと一致する。
- n≤8で全順列列挙から工程目的値の真の最小値を求める。SAが常に到達するとは要求せず、返した値が独立評価と一致し、初期解より悪くないことを要求する。
- n≤7で全集合分割を列挙し、構造目的関数の評価を独立に照合する。階層法／SA／GAを大域最適と誤認するテストにしない。
- SAの差分評価は愚直な全再計算と一致する。受理／拒否境界は注入した乱数で確定的に試す。
- MCLの各列和≈1、値が非負有限、孤立要素の保持、未収束状態と上限処理、同点抽出規則を検証する。
- 同seedの同一手法は同じ結果。異なるseedが必ず異なる結果になるとは要求しない。
- 表示フィルタや色スケール変更で解析結果は不変。解析閾値変更では古い結果を新条件の結果と表示しない。

指標比較の数値許容差は原則 `abs(a-b) ≤ 1e-9 × max(1,abs(a),abs(b))`。手法の同点判定など固有の差分閾値は別に明記する。

### 13.3 入出力・画面・配信テスト

1. CSVとXLSXから同じDSMを取り込み、正規化行列・方向・IDの対応が一致する。
2. XLSXを出力して再解析し、数値・ラベル・並び順・所属・条件を照合する。元行列と解析行列を取り違えない。
3. JSON保存→再読込→同条件再実行で結果が再現する。
4. HTMLをfile://で開き、ネットワークを遮断した状態で検索・ズーム・詳細表示できる。
5. ラベル `<img src=x onerror=...>`、`</script>`、`=HYPERLINK(...)` を入れてもHTML内で実行されず、XLSXで式・リンクが作られない。
6. 実行→取消→再実行、入力差し替え→遅れて到着した旧run応答、Worker異常終了で状態が混ざらない。
7. `/test-repo/`配下でページ、Worker、サンプル、動的チャンク、ダウンロードが動く。
8. キーボードのみで取込・設定・実行・セル詳細・出力へ到達できる。
9. n=100/200/500、密度0/1%/10%/100%を計測。手法の対応上限でボタンが正しく制限される。
10. アプリ読み込み後の操作中、入力データを含む外部リクエストが発生しない。

文献ベンチマークはライセンスと配布許可を記録したものだけ同梱する。論文図から推測した行列を正解として使わない。IGTA系の照合用データが非公開ならその制限を報告する。
