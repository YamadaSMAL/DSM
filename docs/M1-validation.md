E2Eの実行コマンド:

```sh
DSM_BROWSER_EXECUTABLE='/Applications/Brave Browser.app/Contents/MacOS/Brave Browser' npm run test:e2e
```

通常は `npx playwright install chromium` 後に `npm run test:e2e`。この端末の専用Chromium取得は展開途中で停止し、中断した。初回E2Eでは未導入ブラウザによる起動失敗、開発時Workerの依存最適化による再読込、selectのラベル解決の問題を確認した。既存Braveへの切替、依存の事前最適化、明示aria-labelで修正し、本番ビルドによる全シナリオ合格を確認した。

## M1受入条件との対応

| 条件 | 検証内容 |
| --- | --- |
| 日本語・不正データの取込 | 日本語、001、BOM、CRLF、明示Shift_JIS、引用符内改行・カンマ、区切り推定／指定。途中空行・不揃い・空ラベル・負値・NaN/Infinity・文字混在・桁区切り・小数カンマ等を拒否 |
| 数式セル拒否 | XLSX式は座標付きで既定拒否。明示キャッシュ利用時だけ有限数値を許可。キャッシュなしは選択しても拒否。再計算しない |
| 方向プレビュー | 入力設定に連動してBがAに依存／BからAへ供給を表示。転置と変換履歴、正規化後の値を単体・E2Eで照合 |
| 500要素初期描画 | 12条件36回の本番ブラウザ計測を保存。Canvasセルに対し見出し・操作・詳細はDOM。500²のDOMセルを生成しない |
| 取消後の元データ保持 | プレビュー取消・再取込・取込中取消・不正ファイル後に確定済みDSMを保持。単体では旧run、revision不一致、20秒上限、Worker異常終了・再作成も確認 |
| XLSX展開制限 | ストリーム実出力量・エントリ数の上限、偽装申告サイズでも停止。SheetJS前に無圧縮再パックし原ZIPの再展開を避ける |
| 必要出力書式 | ヘッダー文字列・数値型・列幅・先頭「=」を文字列として保つXLSX往復を技術検証。出力UIはM3 |

追加の確認:

- CSVとXLSXで正規化値・ラベル・ID・解析入力ハッシュが一致し、原ファイルハッシュは異なる。
- 列順不一致は案を提示し、適用を明示するまで確定不可。重複ラベルは位置一致のみ許可。
- 記号・空欄・対角特例を暗黙変換せず、変換件数・履歴を保存。元セル表を保持。
- 非対称、非ゼロ対角、全0を警告し、1要素を許可。
- XLSXの複数シート・範囲、結合・日付・真偽値・エラー拒否、巨大な申告範囲、破損・非対応形式を検証。
- 検索は重複ラベルの全件とIDを表示。ズーム、ドラッグパン、クリック、矢印セル移動、DOM詳細と選択行表を実操作。
- HTML風のラベルをReactの文字列として表示し、img要素を生成しない。ブラウザE2E中の外部リクエストは0件。
- M0の67テストと各200ケースの性質テストを引き続き通過。既存domainを共用し原バッファを変更しない。

## 未確認事項・引継ぎ

Chrome／Edge／Firefox／Safariの製品別互換性と手動の支援技術確認は未実施。Braveのheadless検証を全ブラウザ動作保証としない。30fpsの継続性能、最大メモリ、500要素XLSXの性能、DPR=2の実機確認は未実施。ZIP展開量上限はプロセス総メモリを保証しない。高度なXLSX装飾は保証しない。

サブパス配信・出力・セッション再読込はM3で確認する。階層法とSCC／順序付け、比較、手動順序・undo/redoはM2。現状の解析Dの表示用前処理状態は、M2の確定した解析入力・ハッシュ・結果条件へ統合する必要がある。IGTA++はM5の研究ゲートを維持する。
