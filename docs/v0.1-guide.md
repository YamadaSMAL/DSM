# v0.1 利用手順と制限

## 起動

Node.js 26.13.1 / npm 11.20.0で確認済み。

```sh
npm ci
npm run dev
```

表示されたHTTP URLを開く。ビルド成果物は `npm run build` → `npm run preview` で確認する。通常アプリのindex.htmlを直接ダブルクリックする起動は対象外。

## 取込・解析

1. サンプル、またはCSV/TSV/.xlsxを選択する。ラベル有無、文字コード、方向、シート・範囲を確認する。
2. 「検証してプレビュー」でエラー、警告、方向、変換履歴を見る。必要な変換だけ明示選択し、再検証する。
3. 「このデータを確定」で有効データを切り替える。取消・不正データでは現在の確定済みデータは失われない。
4. 構造／工程を選び、閾値と二値化、構造ならkとαを設定し「解析を実行」。構造は平均連結、工程はSCC・先行順・Bandを計算する。
5. 結果と現在ビューを比較する。手動順序変更は元結果を保持する。上下矢印またはドラッグで移動、undo/redo、元順・解析順への復帰が使える。

行が列に依存し、情報は列→行へ流れる。構造用Sは双方向をmeanで対称化した無向重み。階層法は大域最適・最適kを保証しない。SCC内部は元index順のため循環とフィードバックが残る。Bandは資源制約を考慮した同時実行の保証ではない。

## 保存・共有

完了結果を選択し「05 · 出力と保存」でタイトルと対象を確認する。保存ファイルは入力情報を含む。

- **単独HTML**: 選択結果と現在ビューの閲覧用。保存後にダブルクリックしてfile://で開ける。オフラインで検索・ズーム・パン・セル詳細を操作できる。再解析はしない。JavaScript無効でも概要と所属表は読める。印刷時は行列画像を表示する。
- **XLSX**: README、SourceMatrix、OriginalDSM、AnalysisDSM、ReorderedDSM、Elements、Metrics、RunConfig、Comparisonの9シート。数値・ラベル・現在ビュー・元解析の区別を保持する。原数式は式ではなく文字列として保存する。
- **セッションJSON**: 原セル、入力A、全完了結果、固定条件、現在ビューとundo/redo、タイトル、共通配色を保存する。再開したい場合は必ずこれを保存する。未実行の設定変更は保存対象外。

セッションを開くには上の「入力ファイル」で.jsonを選択し、検証・プレビュー後に確定する。条件を復元して再実行できる。元ファイルのバイト列やファイル選択状態は復元しない。原ファイル自体を再解析したい場合は別途保管する。ページを再読込すると、保存していないデータは失われる。自動保存・クラウド送信は行わない。

XLSXの行列を再取込する際は、1行目の説明を除く範囲を指定する。3要素ならOriginalDSMのA2:D5。AnalysisDSM/ReorderedDSMを読み込むと元Aではなく解析・並べ替え済みの行列を入力することになる。

## 上限・対応状況

| 項目 | 制限 |
| --- | --- |
| CSV/XLSX | 20MiB、1〜500要素、ラベル200文字 |
| XLSX展開 | 実展開量100MiB、10,000エントリ、取込20秒 |
| セッション | UTF-8 JSON、64MiB、100結果、ビュー履歴100変更、原セル文字列・式は各1Mi文字まで |
| 解析・出力・復元 | 30秒上限。取消・失敗時は確定済みデータを保持 |
| XLSX出力 | 単一原セル文字列は32,767文字まで。高度な装飾は保証しない |
| セッション互換 | schemaVersion=1、同梱された手法・実装版のみ。未知版は拒否 |

.xls・.xlsm・暗号化ブック、負の関係、複数関係、セル編集、共同編集、M4以降の探索は未対応。XLSXの結合・日付・真偽値・エラーセルは拒否。数式の保存済み数値利用は明示設定が必要で、再計算せず古い可能性がある。

Braveで本番ブラウザ操作とオフラインHTMLを検証。Chrome/Edge/Firefox/Safariの製品別互換性、DPR=2実機、継続30fps、最大メモリは未確認。入力・ZIP・JSONの上限はプロセス全体のメモリ上限ではない。

## GitHub Pages公開準備

公開先は未設定。ローカル検証とworkflowの準備まで完了し、外部公開は行っていない。

1. 公開先のリポジトリを決め、Settings → PagesのSourceをGitHub Actionsにする。
2. リポジトリ変数DSM_BASE_PATHをユーザーサイト／独自ドメインなら `/`、プロジェクトなら `/repository-name/` に設定する。
3. 公開内容を確認してDSM_PAGES_ENABLEDを `true` に設定し、mainへのpushまたは手動workflowを実行する。
4. Actionsの検証・deploy成功後、公開URLでも取込・Worker・保存・オフラインHTMLを確認する。

GitHub上の実行・権限・公開URLは未確認。ローカルのサブパス確認は以下で再現できる。

```sh
npx playwright install chromium
npm run test:e2e
npm run test:subpath
```
